# MCP-сервер бронювання — Ruta Resort Polyana

Один URL, який гість вставляє у свій **Claude** або **ChatGPT** — і далі бронює номер
просто в чаті: «знайди мені номер на двох з 12 по 15 вересня».

Це той самий підхід, що зробило «Сільпо» для свого е-кому, але спрощений під готель.

---

## Головна ціль

> Гість зі свого AI-асистента має **перевірити наявність, ціну й створити бронювання**
> у нашій CRM — без дзвінка на рецепцію і без переходу на сайт.

Усе інше (лояльність, історія візитів, апсейл спа) — це вже наступні кроки.

---

## Ключове спрощення: OAuth на старті **не потрібен**

«Сільпо» знадобився OAuth 2.1, бо в них кошик, бонуси й історія покупок **конкретного акаунта**.

У готелю новий гість — **анонімний**. Щоб забронювати, потрібні лише дати, номер, ім'я й телефон.
Тому:

| | Що робимо | Авторизація |
|---|---|---|
| **Фаза 1 (цей код)** | Пошук, ціни, створення броні, перевірка/скасування броні | Немає. Доступ до чужої броні захищено парою **код бронювання + телефон** |
| **Фаза 2 (пізніше)** | Особистий кабінет: історія візитів, бонуси, зміна броні | OAuth 2.1 + PKCE поверх Фази 1 |

Це економить ~80% роботи на старті: OAuth-сервер, реєстрація клієнтів, ротація токенів —
усе це не потрібно, щоб гість забронював номер.

**Гроші сервер не списує.** `create_booking` створює бронь у статусі `pending`
і повертає посилання на оплату/підтвердження, яке гість відкриває сам.

## Швидкий старт (2 хвилини, без CRM)

```bash
cd mcp-booking
npm install
npm run dev          # http://localhost:8787/mcp
```

Сервер стартує з демо-даними (`CRM_PROVIDER=mock`) — реальні категорії номерів
Ruta Resort Polyana, правдоподібні ціни, робочий цикл бронювання. Можна одразу
підключати в Claude і показувати керівництву, як це виглядає.

Перевірка:

```bash
npm test         # 8 e2e-тестів справжнім MCP-клієнтом
npm run build    # збірка в dist/
```

## Як гість підключає це до себе

### Claude (веб або десктоп)

1. **Settings → Connectors → Add custom connector**
2. URL: `https://mcp.rutapolyana.com/mcp`
3. Готово — у чаті з'являються інструменти готелю.

### ChatGPT

1. **Settings → Connectors → Add custom connector** (потрібен режим розробника / плановий доступ)
2. Той самий URL: `https://mcp.rutapolyana.com/mcp`

### Локальна перевірка

```bash
npx @modelcontextprotocol/inspector
# Transport: Streamable HTTP → http://localhost:8787/mcp
```

На сайті потім достатньо блоку «Забронювати через свій AI» з цим URL і кнопкою «Скопіювати».

## Що вміє сервер

| Інструмент | Дія |
|---|---|
| `search_availability` | Вільні номери, тарифи й **актуальні ціни** на дати |
| `list_room_types` | Опис категорій номерів: місткість, ліжка, площа, зручності |
| `create_booking` | Створює бронь у статусі `pending` + посилання на оплату |
| `get_booking` | Деталі броні за кодом + телефоном |
| `cancel_booking` | Скасування броні за кодом + телефоном |
| `get_hotel_info` | Довідка: що включено, харчування, wellness і чани, екскурсії, правила, контакти |

Плюс ресурс `hotel://rutapolyana/overview` (картка готелю) і промпт `plan_stay`
(готовий сценарій «підбери мені відпочинок»).

Сервер має вбудовані **інструкції для моделі**: не вигадувати ціни, показувати підсумок
перед бронюванням, не вигадувати контакти гостя, а в складних випадках — давати телефон рецепції.

## Підключення реальної CRM

Один рядок в `.env`:

```env
CRM_PROVIDER=rest
CRM_BASE_URL=https://crm.rutapolyana.com/api/v1
CRM_API_KEY=...
```

Далі два варіанти:

1. **CRM вміє потрібні виклики** → правите функції `map*` у `src/crm/rest.ts` під назви полів вашої CRM.
2. **CRM не вміє** → ваш розробник пише тонкий проксі-сервіс за контрактом із
   [`docs/CRM-CONTRACT.md`](docs/CRM-CONTRACT.md) — це 4 ендпоінти.

Уся решта коду не змінюється: MCP-шар відв'язаний від CRM інтерфейсом `CrmAdapter`.

## Деплой

```bash
docker build -t rutapolyana-mcp .
docker run -p 8787:8787 --env-file .env rutapolyana-mcp
```

Підійде будь-який хостинг Node (Fly.io, Railway, Hetzner + Caddy). Потрібні:

- **HTTPS** — MCP-клієнти не приймають http для публічних серверів;
- піддомен, напр. `mcp.rutapolyana.com`;
- сервер **stateless** — можна тримати кілька інстансів за балансувальником.

---

## Безпека

- Немає доступу до чужих даних: бронь відкривається лише за парою **код + телефон**.
- Rate limit на IP (`RATE_LIMIT_MAX`, за замовчуванням 60 запитів/хв).
- Ключ CRM живе тільки на сервері — AI-клієнт гостя його не бачить.
- Валідація дат: не в минулому, не довше `MAX_NIGHTS`, не далі `MAX_ADVANCE_DAYS`.
- Запис у CRM — лише `pending`-бронь і скасування. Ніяких платежів через MCP.
